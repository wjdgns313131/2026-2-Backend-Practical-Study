1. Dockerfile, 이미지, 컨테이너는 각각 어떤 역할을 하나요?

* Dockerfile: 애플리케이션을 실행하기 위해 필요한 환경과 설정을 작성한 파일이다.
* 이미지(Image): Dockerfile을 기반으로 생성한 실행 환경의 패키지로, 애플리케이션과 필요한 의존성을 포함한다.
* 컨테이너(Container): 이미지를 기반으로 생성되어 실제로 실행되는 독립적인 환경이다.

즉, Dockerfile을 이용해 이미지를 빌드하고, 해당 이미지를 실행하면 컨테이너가 생성된다. 이를 통해 서로 다른 환경에서도 일관되게 애플리케이션을 실행할 수 있다.

2. AWS와 EC2는 각각 무엇인가요?

**AWS(Amazon Web Services)**는 서버, 데이터베이스, 스토리지 등 다양한 IT 인프라를 인터넷을 통해 제공하는 클라우드 플랫폼이다.

**EC2(Elastic Compute Cloud)**는 AWS에서 제공하는 가상 서버 서비스이다. 사용자는 직접 물리 서버를 구축하지 않고도 EC2 인스턴스를 생성하여 애플리케이션을 배포하고 실행할 수 있다.

이번 실습에서는 EC2에 Docker 컨테이너를 실행하여 Spring Boot 애플리케이션을 배포했다.

3. 외부에서 EC2에 배포한 API를 호출할 때, IP 주소와 포트는 어떤 역할을 하나요?

* IP 주소: 네트워크에서 요청을 보낼 서버를 식별하는 주소이다.
* 포트(Port): 해당 서버에서 실행 중인 여러 서비스 중 어떤 서비스에 요청을 전달할지 구분하는 번호이다.

예를 들어 http://서버IP:8080/deploy-check로 요청하면 IP 주소를 통해 EC2 서버를 찾고, 8080 포트를 통해 Spring Boot 애플리케이션에 접근한다.

외부에서 접근하려면 EC2 보안 그룹에서도 해당 포트의 인바운드 트래픽을 허용해야 한다.

4. 추가 학습: 실제 서비스 운영에 필요한 요소

실제 서비스를 운영하려면 서버 외에도 여러 요소가 필요하다.

* RDS: AWS에서 제공하는 관리형 관계형 데이터베이스 서비스로, 애플리케이션의 데이터를 지속적으로 저장하고 관리할 수 있다.
* 도메인과 HTTPS: 도메인은 사용자가 IP 주소 대신 기억하기 쉬운 이름으로 서비스에 접근하도록 하며, HTTPS는 통신 내용을 암호화한다.
* 로드 밸런서(Load Balancer): 여러 서버에 요청을 분산하여 특정 서버에 부하가 집중되는 것을 방지한다.
* 오토 스케일링(Auto Scaling): 트래픽 증가에 따라 서버 수를 자동으로 늘리고, 감소하면 줄여 효율적으로 운영할 수 있도록 한다.
* Elastic Beanstalk: 서버 환경 구성과 배포, 확장 등을 자동화하여 애플리케이션 배포를 간편하게 해주는 AWS 서비스이다.

5. 느낀 점

이번 실습을 통해 로컬에서 개발한 Spring Boot 애플리케이션을 Docker 이미지로 만들고, Docker Hub를 거쳐 EC2 서버에 배포하는 전체 과정을 경험했다.

특히 로컬 환경과 서버의 CPU 아키텍처 차이로 발생한 오류를 해결하면서 배포 환경의 중요성을 이해했다. 또한 애플리케이션을 실행하는 것뿐만 아니라 네트워크 설정, 데이터베이스, 보안, 트래픽 관리까지 고려해야 실제 서비스를 안정적으로 운영할 수 있다는 점을 배웠다.
